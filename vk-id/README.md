# Вход через VK ID и регистрация по почте для «Топиарий Сад»

Обновление от 12 ноября 2026 года. Задача Проективы №351552 и дополнение по просьбе руководителя.

**Это отдельная версия на Node.js.** В текущей основной версии руководитель использует PHP. Для его хостинга подготовлены корневые файлы репозитория и инструкция `README_AUTH.md`. Для PHP-сайта не нужно заменять корневую страницу этим `index.html` и запускать данный сервер.

## Что готово

- В шапке есть ссылка «Войти». Она ведёт к отдельному блоку под каталогом.
- В блоке остаётся синяя кнопка «Войти через VK ID».
- Рядом доступны вход по почте и регистрация с почтой, паролем и повтором пароля.
- После регистрации пользователь входит на сайт. Есть выход из аккаунта и повторный вход.
- Аккаунты по почте сохраняются в SQLite после перезапуска. В базе лежат хеши паролей с индивидуальной солью, исходные пароли не сохраняются.
- Блок «Заказать индивидуальный топиарий» с именем и телефоном — форма заказа. Это не регистрация.

Нужно брать **всю папку `vk-id` из ветки `vk-id-351552`**, включая новый файл `accounts.mjs`. Копирования одного HTML-файла недостаточно. Работу с реальным VK после размещения ещё необходимо проверить. Сбер ID остаётся отложенным.

## Запуск на компьютере

Нужен Node.js **24 LTS**. Дополнительные пакеты не требуются. Используется встроенный модуль `node:sqlite`.

Из папки сборки выполните команду.

```powershell
node server.mjs
```

Откройте `http://127.0.0.1:8080/#login`. Регистрация и вход по почте работают без параметров VK. Кнопка VK будет выключена до его настройки.

По умолчанию база создаётся **вне папки исходников**.

- Windows — `%LOCALAPPDATA%/topiary-sad/accounts.sqlite`.
- Linux — `$XDG_DATA_HOME/topiary-sad/accounts.sqlite`, при отсутствии переменной — `~/.local/share/topiary-sad/accounts.sqlite`.

При проверке используйте вымышленную почту и отдельный тестовый пароль. Не загружайте базу пользователей в GitHub или в папку публичных файлов сайта.

## Как разместить на хостинге

1. Обновите всю папку приложения файлами `vk-id`. Ранее работавшую серверную часть нужно перезапустить. Убедитесь, что тариф поддерживает Node.js 24 и HTTPS. Одно копирование файлов в `/www/topiary-sad.ru` не запускает сервер.
2. Создайте постоянную папку данных **вне исходников и публичного каталога**. Она должна быть доступна для записи только пользователю серверного процесса. Для одного процесса достаточно отдельного SQLite-файла. Укажите его в `AUTH_DB_PATH`. При обновлении сайта сохраняйте этот файл и делайте закрытые резервные копии. Пример `/var/lib/topiary-sad/accounts.sqlite` — путь, папку и права на который должен подготовить администратор.
3. Задайте параметры запуска. ID и адрес возврата VK взяты из документа руководителя от 11 ноября.

   ```sh
   SITE_ORIGIN=https://www.topiary-sad.ru \
   VK_CLIENT_ID=54889426 \
   VK_REDIRECT_URI=https://www.topiary-sad.ru/auth/vkid \
   AUTH_DB_PATH=/var/lib/topiary-sad/accounts.sqlite \
   node server.mjs
   ```

   Пример PowerShell, где база остаётся в стандартной личной папке данных.

   ```powershell
   $env:SITE_ORIGIN = 'https://www.topiary-sad.ru'
   $env:VK_CLIENT_ID = '54889426'
   $env:VK_REDIRECT_URI = 'https://www.topiary-sad.ru/auth/vkid'
   node server.mjs
   ```

   Если VK пока не подключается, уберите обе переменные `VK_CLIENT_ID` и `VK_REDIRECT_URI`, сохранив `SITE_ORIGIN`. Тогда будет работать только почта. Одна переменная VK без другой считается ошибкой конфигурации.

4. Направьте запросы HTTPS-сайта в процесс Node.js на `127.0.0.1:8080`. Пример фрагмента для администратора существующего HTTPS-сайта Nginx.

   ```nginx
   location / {
       proxy_pass http://127.0.0.1:8080;
       proxy_set_header Host $host;
       proxy_set_header X-Forwarded-Proto $scheme;
   }
   ```

   Администратор сохраняет настройки сертификата, настраивает переход HTTP → HTTPS и постоянный запуск процесса. Node.js слушает только loopback. Если нужен другой порт, задайте `PORT`. Не включайте журналирование тел запросов регистрации и входа — там передаётся пароль.

5. Откройте `https://www.topiary-sad.ru/api/auth/session`. До входа при настроенном VK ожидается ответ.

   ```json
   {"authenticated":false,"providers":["email","vk"]}
   ```

   Только `"email"` в списке означает, что почта доступна, а VK не настроен. Ответ 404 означает, что запрос пока не попал в серверную часть этой сборки.
6. На странице `/#login` проверьте создание тестового аккаунта по почте, обновление страницы, выход и повторный вход. Затем проверьте вход собственным аккаунтом VK и отмену входа. Откройте сайт без `www` — сервер должен перевести его на настроенный основной адрес.

`SITE_ORIGIN` — основной HTTPS-адрес **без завершающего слэша и пути**. Он должен совпадать с доменом `VK_REDIRECT_URI`. Когда VK настроен, основной адрес также можно получить из его адреса возврата. Без обеих настроек регистрация допускается только через localhost, а не через произвольный внешний домен.

## Что проверено и что остаётся

Пройдены 26 автоматических сценариев. Отдельно в браузере проверяются создание аккаунта, обновление страницы, выход, неверный пароль и повторный вход. Проверки VK используют подставные ответы провайдера. Это не подтверждение настоящего входа в размещённый сайт.

Команда запуска автоматических проверок.

```sh
node --test --test-concurrency=1 server.test.mjs email-auth.test.mjs
```

**В этой версии нет отправки писем, подтверждения владения почтой и восстановления забытого пароля.** Почта пока является логином. Для писем нужно согласовать отправителя и подключить почтовый сервис, затем добавить подтверждение и восстановление. Не представляйте текущую регистрацию как регистрацию с подтверждённой почтой. Телефон и SMS-вход не реализованы.

Аккаунты по почте пока хранятся в отдельной SQLite-базе этой сборки. Интеграция с общей базой заказов и личным кабинетом команды не выполнялась. Аккаунты VK и почта автоматически не объединяются. Сессия живёт один час и хранится в памяти одного процесса. После перезапуска нужно войти снова, сам аккаунт по почте сохраняется. Для нескольких серверных процессов нужно общее хранилище сессий.

Лимит входа — 10 попыток на почту и 30 на сетевой адрес за 15 минут. `X-Forwarded-For` не принимается на веру. За одним reverse proxy адрес будет общим для посетителей. Перед публичной эксплуатацией администратору нужно настроить ограничение на доверенном прокси либо согласовать получение реального IP. Эта сборка предназначена для проверки командой перед общим запуском, включая перечисленные ограничения.

## Маршруты и защита

| Маршрут | Действие |
| --- | --- |
| `POST /api/auth/register` | Принимает `email`, `password`, `confirmPassword`, создаёт аккаунт и сессию. |
| `POST /api/auth/login` | Проверяет почту и пароль, заменяет текущую сессию. |
| `POST /api/auth/logout` | Удаляет текущую сессию на сервере и cookie браузера, в том числе после VK. |
| `GET /api/auth/session` | Возвращает состояние входа, список провайдеров и почту только текущего вошедшего пользователя. |
| `GET /api/auth/vk/start` | Создаёт одноразовую попытку с PKCE и переводит в VK ID. |
| `GET /auth/vkid` | Возврат VK по адресу, зарегистрированному руководителем. |
| `GET /api/auth/vk/callback` | Поддержка прежней конфигурации callback. |

POST-запросы принимаются в JSON только с того же `Origin` и `Host`. Пароль — от 15 до 128 символов, поддерживаются пробелы и кириллица. Для хеширования применяется scrypt `N=131072, r=8, p=1`, случайная соль 16 байт и ключ 64 байта. Не более двух вычислений хеша одновременно. У почты убираются краевые пробелы, регистр приводится к нижнему. Повторная регистрация не меняет пароль существующего аккаунта.

Сайт отдаёт только явно разрешённые публичные файлы. База, исходники сервера и тесты недоступны по HTTP. Cookie сессии имеет `HttpOnly`, `SameSite=Lax` и, для HTTPS, `Secure` с префиксом `__Host-`. Ошибка входа одинакова для отсутствующей почты и неправильного пароля. Пароли, ключи и сессии не записываются в логи приложения. По HTTP допустим только локальный запуск.

В VK проверяются одноразовый `state`, cookie попытки, PKCE и ответ обмена. В каждой установке обрабатывается только путь из `VK_REDIRECT_URI`. Адрес в кабинете VK ID должен совпадать полностью, включая `www` и путь. Токены VK не выдаются браузеру и не сохраняются. Секретный ключ VK в HTML или GitHub добавлять не нужно.
