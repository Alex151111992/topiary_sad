# Прототип входа через VK ID для «Топиарий Сад»

Задача Проективы №351552. В этой версии подключается VK ID. Сбер ID отложен до решения руководителя проекта.

## Локальный запуск

Из папки проекта запустите сервер на Node.js 22 или новее. Устанавливать пакеты не нужно.

```powershell
node server.mjs
```

Откройте `http://127.0.0.1:8080/#login`. Без параметров VK ID витрина работает, а кнопка входа показывает, что подключение ещё не настроено.

Автоматические проверки запускаются командой `node --test server.test.mjs`. Они вызывают обработчики сайта и подставляют ответы VK. Проверяются обмен кода, создание и истечение сессии, отмена, неверный `state`, повторный возврат и ошибки провайдера.

## Первый вход через настоящий VK ID

1. Согласуйте владельца веб-приложения VK ID и адрес тестового сайта. Для внешнего адреса нужен HTTPS. Сервер слушает `127.0.0.1`, поэтому на тестовом хосте его можно подключить к HTTPS через обратный прокси.
2. Зарегистрируйте веб-приложение в кабинете VK ID. Добавьте точный адрес возврата с путём `/api/auth/vk/callback`.
3. Перед запуском укажите ID приложения и тот же адрес возврата. В примере значения условные.

   ```powershell
   $env:VK_CLIENT_ID = '12345'
   $env:VK_REDIRECT_URI = 'https://shop.example.test/api/auth/vk/callback'
   node server.mjs
   ```

4. Откройте сайт по зарегистрированному адресу и нажмите «Войти через VK ID». После подтверждения VK должен вернуть пользователя к разделу входа, где сайт покажет «Вы вошли в аккаунт». Проверьте также отмену входа в отдельной сессии браузера.

## Что делает сервер

| Маршрут | Действие |
| --- | --- |
| `GET /api/auth/vk/start` | Создаёт одноразовую попытку входа и отправляет пользователя в VK ID. |
| `GET /api/auth/vk/callback` | Проверяет браузер и `state`, обменивает код с PKCE на сервере, создаёт сессию и возвращает к витрине. |
| `GET /api/auth/session` | Подтверждает сессию сайта по cookie и сообщает, доступен ли VK ID. |

Токены VK остаются внутри операции обмена. Браузер получает отдельную cookie сайта с `HttpOnly`, `SameSite=Lax` и `Secure` при HTTPS. Попытки и сессии временно хранятся в памяти одного процесса и сбрасываются при его перезапуске. Сквозная проверка с VK остаётся до регистрации приложения и настройки адреса возврата.
