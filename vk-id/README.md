# Прототип входа через VK ID для «Топиарий Сад»

Задача Проективы №351552. В этой версии подключается VK ID. Сбер ID отложен до решения руководителя проекта.

## Локальный запуск

Из папки проекта запустите сервер на Node.js 22 или новее. Устанавливать пакеты не нужно.

```powershell
node server.mjs
```

Откройте `http://127.0.0.1:8080/#login`. Без параметров VK ID витрина работает, а кнопка входа показывает, что подключение ещё не настроено.

Автоматические проверки запускаются командой `node --test server.test.mjs`. Они вызывают обработчики сайта и подставляют ответы VK. Проверяются обмен кода, создание и истечение сессии, отмена, неверный `state`, повторный возврат и ошибки провайдера.

## Настройки приложения Кривдина

В документе, переданном 11 ноября, указаны ID приложения `54889426` и адрес возврата `https://www.topiary-sad.ru/auth/vkid`. Сервер принимает этот путь. Домен с `www` используется для входа и сессии. При обращении к настроенному серверу через другой домен он сначала переводит браузер на `www`, чтобы cookie попытки входа сохранилась до возврата из VK.

У прежних установок сохранена поддержка `/api/auth/vk/callback`. В каждой установке обрабатывается тот путь, который указан в `VK_REDIRECT_URI`. Адрес в кабинете VK ID должен точно совпадать с этим значением, включая `www` и путь.

## Размещение на хостинге

1. Заберите папку `vk-id` из этой ветки. Для сборки нужен работающий процесс Node.js 22 или новее и HTTPS-домен. Проверьте в панели хостинга или у поддержки возможность запуска Node.js и подключения его к домену. Простое копирование файлов в `/www/topiary-sad.ru` запускает только статическую часть сайта.
2. Разместите папку сборки в каталоге приложения. Перед запуском задайте два параметра. Команда для пробного запуска в Linux из папки сборки выглядит так.

   ```sh
   VK_CLIENT_ID=54889426 VK_REDIRECT_URI=https://www.topiary-sad.ru/auth/vkid node server.mjs
   ```

   Для запуска на Windows используйте PowerShell.

   ```powershell
   $env:VK_CLIENT_ID = '54889426'
   $env:VK_REDIRECT_URI = 'https://www.topiary-sad.ru/auth/vkid'
   node server.mjs
   ```

3. В панели приложений или настройках веб-сервера направьте запросы HTTPS-домена в этот процесс на `127.0.0.1:8080`. Для постоянной работы используйте службу сервера или управление процессом из панели хостинга. Поддержке хостинга можно передать следующий фрагмент Nginx для существующего HTTPS-сайта. Остальную конфигурацию, включая сертификат, сохраняет администратор.

   ```nginx
   location / {
       proxy_pass http://127.0.0.1:8080;
       proxy_set_header Host $host;
       proxy_set_header X-Forwarded-Proto $scheme;
   }
   ```

   Внешние HTTP-запросы должны перенаправляться на HTTPS. Порт 8080 слушает только локальный интерфейс сервера. Сборку целиком обслуживает Node.js, который отдаёт только разрешённые публичные файлы.
4. Откройте `https://www.topiary-sad.ru/api/auth/session`. До входа ожидается JSON `{"authenticated":false,"providers":["vk"]}`. Ответ 404 означает, что этот адрес пока обслуживает другой сайт или запрос не дошёл до процесса Node.js. Пустой список `providers` означает, что процесс запущен без настроек приложения VK ID.
5. Откройте `https://www.topiary-sad.ru/#login`, нажмите «Войти через VK ID» и пройдите вход собственным аккаунтом. После возврата ожидается сообщение «Вы вошли в аккаунт». Обновите страницу и проверьте сохранение входа, затем проверьте отмену входа в отдельной сессии браузера. Отдельно откройте сайт без `www` и убедитесь, что настроенный сервер переводит его на `www`.

## Что делает сервер

| Маршрут | Действие |
| --- | --- |
| `GET /api/auth/vk/start` | Создаёт одноразовую попытку входа и отправляет пользователя в VK ID. |
| `GET /auth/vkid` | Принимает возврат из приложения Кривдина, проверяет `state` и обменивает код на сервере. |
| `GET /api/auth/vk/callback` | Проверяет браузер и `state`, обменивает код с PKCE на сервере, создаёт сессию и возвращает к витрине. |
| `GET /api/auth/session` | Подтверждает сессию сайта по cookie и сообщает, доступен ли VK ID. |

Токены VK остаются внутри операции обмена. Браузер получает отдельную cookie сайта с `HttpOnly`, `SameSite=Lax` и `Secure` при HTTPS. Попытки и сессии временно хранятся в памяти одного процесса и сбрасываются при его перезапуске. Для этой сборки нужны ID приложения и адрес возврата. Секретный ключ в HTML, GitHub и настройки этой сборки добавлять не требуется. Сквозная проверка с настоящим VK остаётся после размещения серверной части и проверки настроек приложения в кабинете владельца.
