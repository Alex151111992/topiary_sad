# Вход на сайт — обновление от 12 ноября 2026

## Коротко для руководителя

Регистрация по почте и паролю добавлена **к вашей текущей PHP-версии сайта**. VK остаётся вторым способом входа. Ссылка «Войти» в шапке переводит к блоку под каталогом. В нём можно выбрать вход или регистрацию по почте. После регистрации человек сразу входит на сайт, затем может выйти и войти снова.

Имя и телефон внизу страницы относятся к форме заказа топиария. Они не используются для регистрации.

Нужен **PHP 8.3 или новее с PDO_SQLITE**, HTTPS и отдельная папка для данных. Проверки выполнены на PHP 8.5. Node.js на хостинге для этой версии запускать не требуется. Папка `vk-id` содержит также отдельный проверенный вариант на Node.js, но запускать обе серверные части одновременно не нужно.

## Что обновить

Заберите последние изменения из ветки `vk-id-351552` в свой рабочий проект. Обновлённые файлы PHP-сайта находятся **в корне репозитория**.

- `index.html` — ваш текущий каталог и форма заказа, плюс отдельный блок входа.
- `auth.css` — оформление нового блока.
- `vk-id/auth.js` — переключение форм, регистрация, вход, выход и состояние аккаунта.
- `vk-auth.php` — текущий обработчик VK, дополненный общими сессиями и маршрутами почты.
- `email-auth.php` — регистрация и проверка пароля, база пользователей и лимиты попыток.
- `.htaccess` — маршруты API и ограничения на служебные файлы.

Ваши корневые `script.js` и `style.css` сохранены. Вёрстка каталога, редактирование товаров и контакты взяты из свежей `main`. Старое логирование полного ответа VK отключено, чтобы токены не попадали в отладочный файл. Обработчик обмена кода VK сохранён.

## Настройка на хостинге

1. Обновите перечисленные файлы, включая скрытый `.htaccess`. Не заменяйте страницу корневым `vk-id/index.html` — это отдельная Node.js-витрина, а не ваш новый каталог.
2. В панели хостинга выберите PHP 8.3+ и убедитесь, что включено расширение **PDO_SQLITE**. Если не знаете, где оно включается, передайте это название поддержке хостинга.
3. Выберите постоянную закрытую папку данных **вне каталога сайта и Git-репозитория**. PHP должен иметь право записи в неё. Укажите полный путь к файлу в переменной `AUTH_DB_PATH`. Например, если сайт находится в `/home/USERNAME/www/topiary-sad.ru`, данные можно держать в `/home/USERNAME/topiary-private/accounts.sqlite`. `USERNAME` — пример, нужно подставить реальный путь аккаунта.

   Переменные задаются в панели приложения/хостинга. Если сервер Apache поддерживает `SetEnv`, можно добавить в начало `.htaccess` строки следующего вида, подставив **свой** путь к данным.

   ```apache
   SetEnv SITE_ORIGIN https://www.topiary-sad.ru
   SetEnv AUTH_DB_PATH /home/USERNAME/topiary-private/accounts.sqlite
   ```

   Если переменная `AUTH_DB_PATH` не задана, используется `$HOME/.local/share/topiary-sad-php/accounts.sqlite`. Когда PHP не получает `HOME`, нужно указать путь явно. База создаётся автоматически. Не кладите её в `/www/topiary-sad.ru`, `vk-id` или репозиторий. При обновлениях сохраняйте базу и делайте закрытые резервные копии. Сессии хранятся в подпапке `sessions` рядом с базой. Существующие сессии из прежней временной папки не переносятся, поэтому после обновления нужно будет войти ещё раз.

4. Проверьте адрес возврата **в кабинете VK ID**. Он должен полностью совпадать с адресом в обработчике. Текущее значение по умолчанию оставлено как в вашей последней `main` — `https://www.topiary-sad.ru/api/auth/vk/callback`. В присланном ранее документе был другой путь, `/auth/vkid`. Если в кабинете зарегистрирован именно он, дополнительно задайте переменную.

   ```apache
   SetEnv VK_REDIRECT_URI https://www.topiary-sad.ru/auth/vkid
   ```

   Оба пути поддерживаются правилами `.htaccess`, но обрабатывается только выбранный адрес возврата. Не меняйте его наугад — сверьте с кабинетом. Секретный ключ не нужен в HTML, GitHub и этой конфигурации. Сайт работает по основному адресу `https://www.topiary-sad.ru`, а запросы API на другой домен перенаправляются на него до установки cookie.

5. Откройте `/api/auth/session` по HTTPS. До входа ожидается.

   ```json
   {"authenticated":false,"providers":["email","vk"]}
   ```

   Ответ 404 означает, что не применились правила маршрутизации. Только `"vk"` в списке означает, что база почтовых аккаунтов недоступна. Ответ 503 означает, что нужно проверить настройки PHP и закрытой папки данных. Полные ошибки и пути пользователю не выдаются.
6. На главной нажмите «Войти», выберите «Зарегистрироваться». Проверьте тестовую регистрацию, обновление страницы, выход и повторный вход. Затем отдельно проверьте настоящий VK своим аккаунтом. Откройте страницу в приватном окне, чтобы исключить старую сессию и кэш скриптов.

## Что проверено

В локальной PHP-сборке через реальные HTTP-запросы проверены регистрация, валидация, запрет повторной регистрации с заменой пароля, состояние сессии, выход, смена сессии при новом входе, неправильный пароль, сохранение аккаунта при перезапуске PHP, ограничение попыток, защита от чужого Origin и закрытие служебных файлов тестовым маршрутизатором. Отдельная Node.js-сборка прошла 26 проверок. Полный вход настоящим аккаунтом VK после обновления на хостинге ещё требуется проверить. Работа именно Apache и его правил `.htaccess` локальным PHP-сервером не подтверждается — это часть проверки после размещения.

Для разработчика, запуск проверок PHP при установленном PHP CLI и Node.js.

```sh
node --test tests/php-auth.test.mjs
```

Если `php` не находится через PATH, задайте переменную `PHP_BINARY` с полным путём к `php` или `php.exe`. Локальный маршрутизатор `tests/php-router.php` работает только с тестовым встроенным PHP-сервером и не предназначен для публичного размещения. Доступ к папке `tests` закрыт правилами Apache.

## Границы текущей версии

**Письма для подтверждения владения почтой и восстановления забытого пароля ещё не подключены.** Сейчас почта служит логином, после регистрации доступен вход с паролем. Подключение писем — следующий отдельный шаг после выбора отправителя и почтового сервиса. Не считать почту подтверждённой и не использовать её как основание для автоматического объединения с VK-аккаунтом.

Телефон/SMS-вход не добавлялся. VK и почта — два независимых способа входа, автоматического объединения аккаунтов нет. Интеграция с общей базой заказов и разграничение прав администратора не входят в это обновление. Прежняя клиентская панель редактирования сама по себе не становится защищённой серверной админкой от появления входа.

В PHP пароли хешируются PBKDF2-HMAC-SHA256 с 600 000 итераций, солью 16 байт и сравнением `hash_equals`. База PHP отдельная от SQLite-базы Node.js, автоматической миграции между ними нет. Cookie сессии — HttpOnly, SameSite=Lax, Secure на HTTPS. Срок сессии — час, выход удаляет её на сервере. Пароли и ответы обмена токенов не журналируются.

Лимиты — 10 попыток на почту и 30 на IP за 15 минут. Переданный клиентом `X-Forwarded-For` игнорируется. Если хостинг отдаёт PHP адрес общего прокси в `REMOTE_ADDR`, поддержке нужно настроить получение реального адреса из доверенного прокси. SMTP-параметры, секреты и реальные пароли в проект добавлять не нужно.

Технические источники — [PHP PDO_SQLITE](https://www.php.net/manual/en/ref.pdo-sqlite.php), [PHP hash_pbkdf2](https://www.php.net/manual/en/function.hash-pbkdf2.php), [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html).
