# Управление каталогом от 16 ноября 2026

## Что готово

Добавлена страница `/admin`: список изделий, поиск по названию и описанию, фильтры по категории и публикации, добавление и редактирование, загрузка фото, живой предпросмотр. Товар можно опубликовать или сохранить как черновик. Опубликованные товары видят все посетители. Черновики и их фотографии доступны только администратору.

Изменения хранятся в общей базе на сервере и сохраняются после перезапуска PHP. Старый режим `?admin` и хранение каталога в localStorage больше не используются. Параметр адреса не даёт никаких прав. Старые персональные правки из localStorage автоматически не переносятся: при необходимости их нужно занести через панель. При первом запуске создаются три исходных товара из прежней версии сайта; реальные фотографии к ним можно загрузить через панель.

Это дополнение к регистрации по почте и входу VK, переданным ранее. Используйте файлы корня этой ветки вместе, не только новую HTML-страницу. Node.js на хостинге не нужен. Отдельный прежний вариант в `vk-id` оставлен для истории; на PHP-хостинге запускается корневая версия.

## Как поставить на хостинг

1. Сохраните резервную копию текущих файлов сайта и **закрытой папки данных**. Не кладите резервную копию базы в публичную папку.
2. Перенесите изменения ветки `admin-catalog-354647` в основной проект. Они включают ранее переданные формы почты/пароля. Основные файлы: `admin.html`, `admin.js`, `admin.css`, `catalog.php`, `assets/catalog-placeholder.svg`, `bin/set-admin.php`; также обновлены `index.html`, `script.js`, `auth.css`, `vk-id/auth.js`, `vk-auth.php`, `.htaccess`.
3. Для PHP нужны `PDO_SQLITE`, `GD` с поддержкой JPEG/PNG/WebP и `fileinfo`. Для размещения на Apache должны работать `mod_rewrite` и правила `.htaccess`. На другом сервере нужно настроить аналогичную маршрутизацию и закрытие служебных файлов.
4. Сохраните действующее значение `AUTH_DB_PATH`: абсолютный путь к базе **вне папки сайта**. Папка должна быть постоянной и доступной PHP на запись. Каталог и роли добавятся в ту же базу без удаления почтовых аккаунтов. Фото хранятся в `catalog-images`, сессии — в `sessions` рядом с базой. Эти папки также не должны быть доступны как статические файлы через сайт. Не меняйте путь при обновлении и включите базу и фото в закрытые резервные копии.
5. Задайте `SITE_ORIGIN` точно по основному адресу сайта, например `https://www.topiary-sad.ru`. Сверьте `VK_REDIRECT_URI` с кабинетом VK. По умолчанию это `https://www.topiary-sad.ru/api/auth/vk/callback`; прежний `/auth/vkid` поддерживается при явной настройке. Последняя main объединена в эту ветку; для совместимости с почтой сохранён ранее проверенный общий PHP-обработчик сессий, добавлены настройка VK_CLIENT_ID через окружение и проверка повторяющихся параметров callback. Настоящий VK-вход на хостинге после установки ещё нужно проверить.
6. Для загрузки фото настройте `upload_max_filesize = 4M` и `post_max_size = 5M` или больше. Если конфигурация PHP не позволяет эти значения, увеличьте лимиты через панель хостинга. Панель самостоятельно принимает только JPEG/PNG/WebP до 4 МБ, до 4096×4096 и до 8 мегапикселей.
7. Откройте главную страницу и создайте свою учётную запись по почте. Проверьте, что вход с её паролем работает. Затем назначьте ей права администратора по следующему разделу.

## Один раз назначить администратора

Никто не становится администратором автоматически. Назначение выполняет владелец сайта через SSH/терминал хостинга или поддержку хостинга. В браузере такой команды нет.

В той же среде PHP, где настроен `AUTH_DB_PATH`, из корня сайта выполните:

```sh
php bin/set-admin.php grant email YOUR_EMAIL
```

Вместо `YOUR_EMAIL` впишите почту **своего уже созданного аккаунта**, в который только что вошли с известным вам паролем. Не назначайте роль по одной лишь присланной чужой почте. Владение почтой письмом в этой версии ещё не подтверждается; если почта уже занята неизвестным аккаунтом, не выдавайте ему права.

Для проверенного VK-аккаунта можно назначить роль по его числовому VK user ID:

```sh
php bin/set-admin.php grant vk YOUR_NUMERIC_VK_ID
```

Для отзыва прав используется та же команда с `revoke` вместо `grant`. Изменение роли действует сразу, перезапуск не нужен. Программа не спрашивает и не сохраняет пароль. Не отправляйте пароли или ключи в переписку/GitHub.

Если SSH нет, попросите поддержку хостинга выполнить эту одноразовую команду с тем же `AUTH_DB_PATH`, что использует сайт. Не пытайтесь открыть `bin/set-admin.php` как страницу: HTTP-доступ закрыт.

## Как пользоваться

После назначения роли обновите страницу аккаунта: появится «Управление каталогом». Можно сразу открыть `https://ВАШ_ДОМЕН/admin`.

- «Добавить изделие»: название, описание, цена, категория, при необходимости фото; справа сразу видно будущую карточку.
- «Изменить»: исправить поля существующего товара и нажать «Сохранить изделие».
- «Сохранить как черновик»: убрать товар из публичного каталога, оставив его для последующей правки.
- «Убрать сохранённое фото»: заменить прежнюю фотографию заглушкой. Новая загруженная фотография имеет приоритет над этой отметкой.
- Фильтры помогают найти нужные товары. После сохранения активные фильтры остаются: например, опубликованный товар исчезнет из списка, отфильтрованного по черновикам. Нажмите «Сбросить», чтобы увидеть всё.

Если кто-то уже изменил открытый товар, панель не перезапишет его молча: сообщит о конфликте. Обновите список и откройте товар заново. Если срок входа истёк, войдите ещё раз.

## Проверка после размещения

1. Без входа и с обычным аккаунтом `/admin` должен показывать отказ, API не должен разрешать чтение списка черновиков или сохранение.
2. Под администратором добавьте тестовое изделие с фото. Обновите страницу и убедитесь, что оно сохранилось.
3. Откройте каталог в отдельном браузере: опубликованное изделие должно быть видно.
4. Переведите его в черновик: оно и его фото должны перестать быть доступны посетителям.
5. Верните публикацию, исправьте цену и проверьте каталог после обновления. Проверьте поиск и оба фильтра.
6. Проверьте вход по почте, выход и настоящий вход VK. Отдельно убедитесь, что ссылки на `/catalog.php`, `/email-auth.php`, `/bin/set-admin.php`, `/.git/config`, `/tests/`, базы и резервные копии не отдают исходники или данные.

Проверка локального PHP-сервера не доказывает правильность правил именно вашего Apache. На другом типе сервера нужен отдельный эквивалент `.htaccess`.

## Технические ограничения

В эту задачу не входят заказы, платежи, подтверждение почты и восстановление пароля письмом, назначение администраторов через веб-интерфейс и редактирование текстов главной страницы. Удаление изделий не добавлено: для снятия с сайта используется черновик.

Фото проверяются по содержимому и размерам, заново кодируются GD, получают случайное имя и хранятся вне web-root; SVG/HTML/исполняемые файлы не принимаются. Поля каталога выводятся как текст. Для изменения нужны серверная роль, сессия, точный Origin и связанный с сессией CSRF-токен. Секретов, реальных паролей и данных пользователей в исходниках нет.

При реализации сверены [руководство PHP по загрузкам](https://www.php.net/manual/en/features.file-upload.php), [PHP getimagesize](https://www.php.net/manual/en/function.getimagesize.php) и [OWASP File Upload Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html). Одна проверка размеров не заменяет проверку формата, поэтому применяется также декодирование и повторное кодирование изображения.
